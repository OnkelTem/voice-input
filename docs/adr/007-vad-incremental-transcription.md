# 007 — VAD + инкрементальная транскрибация

## Статус

Accepted

## Контекст

Изначально транскрибация запускалась только после того, как пользователь
отпускал клавишу, и обрабатывала весь наговорённый текст одним куском. При
длинных диктовках это неудобно — текст не виден до самого конца записи.

## Решение

Добавить энергетический VAD (Voice Activity Detection) прямо в `callback`
sounddevice, который вызывается ~32 раза в секунду (блоки по 512 сэмплов на
16 kHz). На каждой паузе длиннее `vad_silence_ms` накопленный сегмент
отправляется в `queue.Queue`. Фоновый поток `transcriber_loop` забирает
сегменты, транскрибирует через whisper-cli и печатает текст через xdotool.

### Ключевые решения

- **RMS-based VAD**: порог `vad_threshold` (по умолчанию 0.005). Блоки с RMS
  выше порога считаются речью, ниже — тишиной.
- **SPEECH_ACTIVE флаг**: предотвращает сплиты тишины после окончания речи.
  Взводится при первом голосовом блоке, сбрасывается после сплита.
- **Очередь с защитой от лавины**: при >5 сегментов в очереди нарезка
  прекращается — всё копится до остановки записи.
- **Пробел после пунктуации**: после `.`, `?`, `!` xdotool печатает пробел,
  чтобы сегменты не склеивались.
- **Короткие сегменты (< vad_min_segment_ms, по умолчанию 300 ms)**
  игнорируются как шум/сбои.

### Конфигурация

Параметры VAD читаются из `~/.config/voice-input/config.toml`:

```toml
vad_threshold = 0.005
vad_silence_ms = 2000
vad_min_segment_ms = 300
```

## Последствия

- Пользователь видит текст инкрементально, по мере появления пауз в речи.
- Внутренняя архитектура усложнилась: появились очередь, фоновый поток,
  VAD-состояние.
- whisper-cli может вызываться чаще (на каждый сегмент), но каждый вызов
  обрабатывает меньше звука.
- При очень быстрой речи без пауз всё работает как раньше — один кусок.
